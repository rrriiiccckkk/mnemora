# 派生记忆不是原始事实

摘要 / Episode 有来源引用，只能说明记录之间有关联，不能证明其中每条断言
都得到原文支持。`source_linked`、置信度、检索排名均不等于事实验证。

维护背景：用户报告一条召回转述将删除对象从 Unsloth Studio 换成 laya-mlx，
下游直接写入报告。未取得实际注入的 kind/contextRef 和形成记录；压缩层串错
仍是待验证假设，搜索不到原句本身不能排除索引、范围或其他转述路径。

## 本次防护

- 统一召回的摘要 / Episode 显式标 `derived_paraphrase`、`not_verified`，
  同时提供带来源引用、角色、时间和截断标志的原文核对窗口。
- 多层摘要沿同 scope 的依赖关系追溯原始事件；最多访问 32 个摘要节点、
  收集 9 个唯一来源 ID，展示 3 条清洗后的 240 字符片段。
- 只读当前有效的 user/assistant 用户对话；不读取生产库来补材料，
  不复活已删除事件、非注入摘要、非活动 Episode 或 hash-only 内容。
- 最终组装时重新读取窗口，旧检索结果不能重放已遗忘的原文。
- 压缩上下文同样区分派生断言与来源；预算不足逐条省略窗口并显式标记。
  必须保留最近对话；连最小标记都放不下时，不插入该摘要。
  已启用统一召回时，附加窗口优先留出最多 128 token 的召回空间；不改配置额度。
- 原文窗口经过现有上下文安全清洗，仍是非权威参考，不成为指令或已接纳结果。

原有 `authority` 和排序权重不变；新增的是投影性质与核对材料。新增文本纳入
最终预算，可能减少可附着的候选。窗口是截断、清洗后的局部材料，不是完整
历史，也不代表当前状态。来源角色为 assistant 更不等于执行已得到独立证实。

## 使用与边界

写安装、删除、迁移、完成状态等背景事实前，核对对象、动作、结果及时间。
问句“不是删了吗？”或要求“请删除”不能代替实际执行记录。
若已有充分原文证据，不因摘要未经验证就机械要求用户再确认；真缺证据时
保留不确定性，而不是采用派生转述的确定口吻。

这不是语义验证器：不会自动判断哪个产品名才正确，也不会修改历史摘要。
离线用例证明标记、核对窗口、scope / 遗忘 / 预算边界，不证明模型一定遵守。
Mac 现场首次错误节点、报告更正和历史派生链纠正，仍需授权原始证据另行处理。
本次没有生产库变更或付费模型调用，也没有真实效果提升结论。
