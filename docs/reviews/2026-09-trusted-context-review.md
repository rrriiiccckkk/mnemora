# 可信自动上下文审查记录

日期：2026-09-17
基线：`bca4549`（v1.29.2）

## 判断与优先级

项目的本地 SQLite、Journal 持久化、来源引用、人工确认、续接、恢复和审计已经构成有价值的基础。下一步优先保证：同一条记忆无论从哪个自动路径到达 Agent，都遵守相同的可信、生命周期和预算规则。功能扩展不能绕过这条边界。

## 本轮已处理

1. **拒绝的 Claim 不再进入自动上下文。** 统一检索候选和图谱补充都经过同一个自动注入资格判定；`rejected`、`contradicted`、`superseded`、失效来源均被排除。手动检索仍可用于审计。
2. **ReasoningMemory 不再绕过投递治理。** 已接纳策略可被手动检索查看，但统一检索不能自动附加；自动投递只能走既有受治理的运行时 delivery 路径。
3. **遗忘沿摘要依赖闭包传播。** 遗忘原始事件或摘要会使所有直接和间接父摘要退出可注入状态，同时保留审计记录。
4. **最终渲染文本统一计入预算。** 统一检索与 ContextEngine 使用同一份 CJK/astral 感知估算器；按最终包装后的文本逐项压缩候选，保留规范引用，必要时先移除可选图谱扩展。

## 后续工作，尚未在本轮实施

1. 建立中文自然问句召回回归集，特别是“我喜欢喝什么茶”这类连续中文查询；在词法、图谱和 embedding 路径分别测量，避免把词法局限误判为整体召回失败。
2. 将跨会话任务续接作为产品主场景：展示已完成、未完成、阻塞、下一步、失败尝试、替代/更正状态和每个结论的来源。
3. 在固定模型与固定预算下运行真实对照评估：无长期记忆、简单检索、Mnemora 三组比较任务续接正确率、重复劳动、过期/否定信息使用率、不相关注入率、token、延迟和人工审核时间；覆盖中文、更正、遗忘和重启。
4. 评估证明收益后，再逐步扩大 ReasoningMemory 到少量可验证的任务经验。关系类型扩张、通用人格建模和大量 Provider 接入不优先。

## 验收原则

从持久化记录一直测到最终 prompt。示例：拒绝一条证据后，任何自动路径均不得附加它；遗忘一个原始事件后，所有依赖它的摘要不得被召回；在配置的预算内，最终附加文本而非中间候选必须满足预算。
