# 给 OpenClaw agent：Mnemora v1.32.5

这是版本交接，不是自动升级、重启或启用诊断的授权。先核对正式 Release 与同提交 Windows/Linux CI；只有另获用户明确授权才在生产端安装或改配置。

新功能是一张默认关闭的“装配留底单”：记录插件当次交给宿主的记忆身份、来源、指纹和截断状态，不保存正文。它不能证明模型实际收到，更不能验证删除/安装等事实。旧案 W1 的原始注入和形成层缺失，不能宣称压缩根因已证实；合成测试不是现场证据。

如用户只授权升级：按既有升级流程核对版本、显式目标安装和数据库入口，保留配置；不要顺手开启诊断或触发额外重启。先按用户授权范围安排持久状态验收。schema 仍为 84。

如用户另外授权短期诊断（Mac/Linux）：

1. 根据目标版本的宿主 schema lookup 核对 `plugins.entries.mnemora.config.contextEngine.assemblyDiagnostics`；使用独占、仓库外、用户自有的规范绝对目录（0700），不使用 symlink、共享目录或生产扩展目录。
2. 只设置授权 scope、`enabled: true`、`directory` 和有效的 `expiresAt`（epoch 毫秒，不超过未来 24 小时）；不要改模型、Journal retention、prompt 预算或召回排序。Windows 首版明确停止记录。
3. 最多留 20 次，每条最多 64 KiB，文件和本地 HMAC 密钥权限 0600。到期/容量停止写入；既有元数据仍在。无文件不代表没有注入；锁/权限/记录异常也可能停止写入，不自动删锁或重试模型。
4. 只转交获授权的少量记录；引用/scope/指纹仍敏感，去敏时保留稳定匿名关联。不要发送 `.assembly-diagnostic-key`。不要导出数据库、完整历史、密钥或整份配置。

若再次发生对象混淆：保留相关留底单和出错报告的局部原句。元数据不能显示具体对象文字，也没有 host turn 投递证明；实际注入正文、相关局部形成链和执行结果仍须单独最小授权，不自行扩大生产取证。

配置与覆盖限制见 [装配留底单说明](assembly-diagnostics.zh-CN.md)。请报告：实际安装版本/提交、是否仍默认关闭；若明确授权开启，再报告 scope 匿名别名、窗口截止、是否生成记录及覆盖缺口。不要把 AI 初评算人工验收，不修改正式三臂实验门槛。
