# Mnemora v1.10.0

## Recall precision and observability

Automatic ContextEngine attachment is now deliberately stricter than manual
search. A local candidate must share a non-generic query anchor. A graph
supplement must share such an anchor or have a semantic score of at least
`0.72`. Generic words such as “memory” and “system” are not sufficient by
themselves. This prevents a generic product question from attaching an
unrelated company merely because its description shares a broad term.

Graph attachment uses at most one seed and one evidenced hop. The bounded local
candidate pool is then selected with deterministic MMR. `unifiedRetrieval`
adds `diversityLambda` (default `0.75`, range `0..1`); `1` retains score-only
ordering.

`unifiedRetrieval.shadowMode` remains opt-in. When enabled, it records a
scope-local query hash and bounded aggregate counts for the real ContextEngine
attachment path. It never stores prompt text, candidate text, identifiers,
sources, or evidence. `kg_recall_metrics` and `mnemora recall metrics` expose
these rows under `unified` beside the existing adaptive-recall metrics.

## Schema migration

Schema 71 adds `mnemora_unified_recall_shadow_runs`. The migration is additive;
it does not backfill telemetry, call a model or network, alter stored memory,
or enable retrieval, shadow telemetry, or automatic context attachment.
