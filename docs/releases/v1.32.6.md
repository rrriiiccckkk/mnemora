# v1.32.6 — Isolated development verification and project dogfood

Pinned OpenClaw authoring checks previously inherited the developer's host
environment. They now use an empty temporary configuration, separate state
and an environment allowlist for both build and validate. A regression test
checks that a foreign invalid host config does not affect metadata validation.
The existing known-metadata-rejection contract remains in place.

Development gains `verify:fast`, one-build full verification, Node 24 setup,
project guidance, an installed-host integration test and a bounded
`project:mnemora` trial using the daily Gateway's public stateless model API.
Full verification preserves Inspector typechecking, CLI executable setup,
all benchmarks and task-resume evaluations. Tests retain the existing serial runner and parent-owned temporary fixture
cleanup, including native database worker exit before removal.

The project trial uses its own config, database and Gateway process. It does
not enable ReasoningMemory delivery or modify the daily host's memory scope.
See [local development](../development.md) for commands and limits.
