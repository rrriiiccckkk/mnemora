# Mnemora v1.2.0

## Multilingual ReasoningMemory shadow retrieval

- Adds a separate, local semantic index for admitted ReasoningMemory records.
  It stores only vector bytes, model identity, input hash, and scope; strategy
  text, prompt text, and evidence remain in their existing governed tables.
- Adds canonical task-type aliases. Existing `debugging`, `investment`,
  `integration`, `report`, and related historical values are mapped at query
  time, without rewriting stored strategies or evidence.
- Supports explicit `cognition.reasoningRuntime.semantic` configuration. It is
  disabled by default and requires the existing local Ollama embedding setting
  to be enabled as well.
- ContextEngine semantic lookup is bounded by an AbortSignal and timeout. Its
  host path falls back to lexical retrieval on provider failure, while the
  explicit semantic API retains timeout/error visibility for callers.
- Adds `semantic-status` and confirmation-gated `semantic-backfill` CLI
  operations for the local reasoning index.

## Observability and migration

- Shadow telemetry now records aggregate `semantic_candidates`, `unmatched`,
  and `task_type_excluded` counters. No query, strategy, memory ID, evidence,
  or source reference is stored in those rows.
- Schema version advances from `62` to `63` via one additive migration. It
  creates `mnemora_reasoning_memory_embeddings` and adds zero-default aggregate
  columns to existing shadow telemetry. Existing memories, outcomes, graph
  evidence, delivery receipts, and canary state are unchanged.

## Verification

- Added regression coverage for Chinese strategy / English runtime matching,
  old task-type aliases, scope isolation, semantic deadline behavior, lexical
  fallback in host assembly, and async ContextEngine assembly.
