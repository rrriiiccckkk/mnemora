# Mnemora v1.8.0

## Governed reasoning intake

Mnemora can now turn a completed ContextEngine user/assistant turn into at
most two **source-linked candidates**: an explicit decision or an observed
task outcome. This is an opt-in capability:

```json5
cognition: {
  reasoningCuration: {
    intake: { enabled: true }
  }
}
```

Each model request uses only the public host runtime completion interface and
has bounded input/output, timeout, and cancellation handling. It can create
neither a durable decision/outcome nor any belief, fact, profile, graph edge,
or strategy. Candidate text is advisory, isolated by scope, and linked to the
captured user and assistant events.

An operator must use the preview/confirmation workflow to keep a candidate:

```bash
mnemora cognition reasoning intake candidates --scope project:alpha
mnemora cognition reasoning intake confirm <candidate-id> --scope project:alpha
mnemora cognition reasoning intake discard <candidate-id> --scope project:alpha
```

Confirmation creates only an `operator_confirmed` decision or outcome. A
model suggestion never becomes a `user_explicit` record. Existing curation may
later form a separate strategy proposal from a confirmed outcome; that
proposal still requires its own promotion and admission steps.

## Schema migration

Schema 69 adds the isolated `mnemora_reasoning_intake_candidates` table. The
migration is additive: it does not invoke a model, backfill candidates, or
alter existing decisions, outcomes, strategies, beliefs, graph data, profiles,
or delivery circuits.

## Validation

plugin validation, and release metadata consistency checks.
