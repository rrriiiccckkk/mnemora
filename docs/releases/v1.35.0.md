# v1.35.0 — Visible failures, measured answers, better recall of replies and multi-session facts

## Highlights

- **End-to-end answer accuracy is now measured.** `npm run eval:longmemeval-qa` runs LongMemEval_S (500 questions) through a reading model and a judge. Under the same 800-token budget, Mnemora answers 72.6%, a bm25 baseline 67.8% and no memory 7.6%. Mnemora uses 13% fewer context tokens than bm25 and is at or above it on every question type. Before this release Mnemora scored 59.0%. See `docs/recall-quality.md`.
- **Fail-open, but visible.** When optional memory work fails (recall, journal search, embedding, compaction, lifecycle, projections), the host turn still succeeds, but the failure is no longer silent. Each failure is counted per day, and `mnemora health` reports the counts. A broken journal index no longer silently returns no recall.
- **"What did you say" prompts.** Prompts that look back at an earlier assistant reply now attach that reply after the matching user turn and rank assistant turns first. Accuracy on these questions rose from 51.8% to 91.1% (bm25: 91.1%).
- **Multi-session and aggregate prompts.** Prompts such as "how many", "in total", "the most", "一共" and "多少" admit weaker matches, because each fact of a count usually sits in one sentence of a long turn. Multi-session accuracy rose from 33.1% to 48.8% (bm25: 41.3%).
- **Host timestamps.** When a host message carries its own time (imported or replayed history), the record keeps it, so recall can say when something was said rather than when it was captured.

## Behaviour changes (please read before upgrading)

1. **Schema v88.** Adds `mnemora_operation_failures`. Rows are kept for 30 days and are content-free: operation, coarse category and count, with no error text, prompts, records or scope names. The migration is additive.
2. **Gateway log.** A failing operation logs at most one line per operation and category every 10 minutes, including the number of suppressed repeats. A steady `recall_assemble` or `journal_search` count means automatic recall is not working.
3. **Recall envelope format.** Recall consumers that parse the envelope strictly need to be updated:
   - `recorded_at` is now ISO 8601 (`2023-05-30T12:20:00.000Z`) instead of epoch milliseconds.
   - Conversation turns carry `role=user|assistant`.
   - A ref that is cited more than once in a packet is rendered once.
   - For conversation turns, `kind` is omitted (it is part of the ref). `authority` and `confidence` are omitted when they equal the role default: user `user_explicit` 1.00, assistant `source_linked` 0.80. Other record kinds are unchanged.
   - `scripts/project-adviser.mjs` accepts both the new and the old format.
4. **Admission rules.**
   - Freshness and length now only affect ranking. They no longer keep a record out of the packet.
   - Aggregate prompts use an admission floor of 0.25 instead of 0.35 and rank assistant turns at ×0.85. This does not apply to prompts that look back at an assistant reply.
   - On abstention questions, attached context grew by about 25 tokens, with no change in abstention accuracy (96.7%).
5. **Packet budget.** The envelope wrapper and the guidance line now count toward `tokenBudget`. With the same budget, slightly less record text may fit, but packets no longer exceed the budget.
6. **Host timestamps.** Values in seconds or milliseconds are accepted. Values before 2000 or more than five minutes in the future are ignored, and the capture time is used instead.

## Fixes

- Assistant replies attached for a look-back prompt are excerpted around the prompt's rare terms and trimmed to fit, instead of being dropped when they are long.
- Excerpts of assistant turns are wider for look-back prompts.
- A test ratchet stops silent `catch` blocks from growing (124 → 104 in this release).
- The QA evaluation retries provider refusals. It also supports `MNEMORA_QA_TYPES` (question-type filter) and `MNEMORA_QA_EMBED_MODEL` (semantic contexts).
- README (English and Chinese), `docs/recall-quality.md`, the roadmap and the usage guides document the health CLI, the QA results and the multi-session findings.

## Known limits

- Multi-session questions are still the weakest type (48.8%). Many evidence turns share no word with the question ("doctors" vs "my dermatologist"), which word matching cannot find; this applies to bm25 too.
- Semantic recall with `all-minilm` did not help multi-session questions. On 99 questions, evidence-turn coverage was 54.2% semantic vs 59.0% lexical, because the semantic gate drops useful lexical hits. Adding semantic hits without gating lexical ones is the next step.
- QA results come from one reading model (MiMo V2.6 Pro, thinking off) on English data. At n=500, differences under about 4 points are within noise.
- Chinese thresholds for a multilingual embedding model are not yet calibrated.
