# Mnemora v1.7.0

## Governed automatic ReasoningMemory curation

Mnemora can now accumulate reusable procedural strategy **candidates** from
explicit confirmed TaskOutcomes, and can periodically ask the host runtime
model to review existing strategies. Both capabilities are opt-in and run only
after a durable ContextEngine turn with a public host runtime LLM.

- Formation creates at most a bounded `pending_review` proposal from a
  source-linked confirmed outcome. It never creates a belief, fact, graph edge,
  profile attribute, or ReasoningMemory directly.
- An operator may preview/confirm promotion of a candidate; that creates only a
  `proposed` strategy. Existing explicit admission remains required before
  retrieval.
- Periodic review creates advisory retain/retire/needs-review proposals only.
  A human must resolve every proposal. Retirement preserves the strategy and
  audit history rather than deleting data.
- Every runtime model call is input/output bounded, timeout- and
  AbortSignal-aware, and uses only OpenClaw's public runtime completion
  capability. There are no provider credentials or direct provider calls.

## Compatibility

Schema 68 is additive. It adds isolated curation-run, formation-proposal, and
review-proposal tables. Migration neither calls a model nor backfills data, and
does not alter existing strategies, outcomes, beliefs, graph data, profiles,
or delivery circuits. Both curation settings default to disabled, preserving
v1.6 behavior.

## Validation

Validated on Node.js 24 with typechecking, the complete test suite, build,
smoke and plugin validation, the supported OpenClaw compatibility gate, release
metadata validation, and offline quality benchmarks.
