# Mnemora v1.14.0 — Related-Edge Semantic Enrichment

## Explain fallback edges without changing topology

- `kg_review` now accepts `kind: "related_edge_semantics"`.
- Its explicit, bounded scan considers active same-scope `related_to` edges
  only when their best retained observation has confidence at least `0.85`,
  the quote directly and directionally states an existing semantic predicate,
  and the endpoints match that predicate's supported types.
- Candidates cover the existing soft vocabulary, including `uses`, `develops`,
  `works_at`, `supplies`, `owns`, and related investment/code predicates.

## Review semantics

- Scan and preview do not modify graph data. Accepted confirmation creates a
  source-linked semantic **label projection** for the exact fallback edge;
  rejection remains inert.
- The original `related_to` edge, its evidence, PPR projection, traversal
  behavior, and weights remain unchanged. An accepted label is returned only
  when the caller explicitly asks for that semantic relationship type.
- No model call, automatic labelling, relationship replacement, or broad
  co-occurrence inference is introduced.

## Migration and compatibility

- Schema version advances from `72` to `73` with additive candidate and review
  tables. Migration never scans, labels, alters, or retires existing data.
- Existing configuration, automatic recall behavior, and default topology
  policy remain unchanged.

## Validation

- Added regression coverage for direct-cue gating, scope isolation,
  preview-hash confirmation, explicit semantic query visibility, PPR topology
  invariance, rejection, hard-forget cleanup, and the v72-to-v73 migration.
