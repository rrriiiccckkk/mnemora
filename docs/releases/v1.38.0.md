# v1.38.0 — A smaller Mnemora: graph governance and research tools removed

## Highlights

- **Graph governance removed.** Graph hygiene, the graph-review worklist and decision gate, related-edge refinement and semantic enrichment, semantic vocabulary review, schema-drift review and repair, and cognition graduation are gone. They were operator-only, off or unused by default, and had no evidence of benefit or use. `kg_review` stays, reduced to `duplicates` (pair with `kg_merge`), `anomalies`, `identity` and `semantic_patterns`, because every `kg_ingest` still writes duplicate candidates that only it reads.
- **Research tools removed.** `kg_insights`, `kg_query`, `kg_query_history`, `kg_timeline`, `kg_compare`, `kg_watch` and `kg_digest` are gone, with the insight analytics (detectors, metrics, explainer) and the query planner, executor, saved queries, watches, timeline and compare. They were only on the `research` and `full` tool surfaces. `kg_export` and `kg_import` stay.
- **What stays.** The graph is unchanged: storage, ingestion, `kg_search`, `kg_related`, `kg_context` graph recall, `kg_merge`, `kg_forget`, `kg_verify`, `kg_export`/`kg_import`, community detection for the Inspector's graph view, and the Inspector. Automatic recall is unchanged; the CI retrieval gate gives the same numbers before and after (all evidence 72, any evidence 90).
- **Size.** TypeScript source is 2.05 MB, down from 2.34 MB in 1.37.0 (about 282 KB or 12 % less). About 7,200 lines of source and tests were deleted across the two commits. The full tool surface has 25 tools instead of 32.

## Behaviour changes (please read before upgrading)

1. **Removed tools.** `kg_insights`, `kg_query`, `kg_query_history`, `kg_timeline`, `kg_compare`, `kg_watch` and `kg_digest` are no longer registered. Agents or scripts that call them must stop doing so; there is no replacement in Mnemora.
2. **`toolSurface: "research"` is now an alias of `"core"`.** It is still accepted so existing configurations load. `"full"` exposes 25 tools.
3. **Removed `kg_review` kinds.** `hygiene`, `worklist`, `schema_drift`, `semantic_vocabulary`, `related_edge_refinements` and `related_edge_semantics` now fail with `review_kind_removed: <kind> was removed in 1.38.0`, instead of being answered as `duplicates`. The `repair_type` parameter and the `invalidated` status are gone from the schema.
4. **Removed operator commands.** `mnemora review gate`, `mnemora review worklist`, `mnemora review vocabulary` and `mnemora cognition graduation`. `mnemora review anomalies preview|confirm` stays.
5. **Ingest no longer records schema-drift candidates.** A relation whose endpoints do not match its expected types is still stored with `endpoint_match: false` on the edge, as before; it just no longer creates a review row.
6. **Scheduled hygiene no longer runs.** `quality.hygiene`, `cognition.graduation`, `insights.*` and the query, watch and digest limits in `query.*` are still accepted but have no effect. `query.maxImportBytes` and `query.maxImportRecords` still apply to `kg_import`.
7. **Inspector research pages are read-only history.** Stored query history, watches, digests and insight snapshots are still shown. Insight snapshots are no longer computed live: without a current stored snapshot the page shows a `truncated` warning.
8. **Library API.** The exports for the removed modules are gone (for example `GraphAnalyticsService`, `GraphQueryService`, `QueryPlanner`, `WatchService`, `normalizeQueryPlan`, the `insights/metrics`, `insights/detectors`, `query/*` research modules and the hygiene exports), as are the corresponding store methods (`reviewSchemaDrift`, `createWatch`, `listQueryRuns`, `readInsightSnapshot`, `queryGraphProjection` and others) and their input and result types.
9. **No schema migration (still v88).** All tables stay, so existing databases open unchanged and earlier releases can still read them. Migrations from older versions are kept, hard forget still clears the legacy review tables, and related-edge labels accepted earlier are still readable through `kg_related(..., semantic_predicates: [...])`.

## Fixes

- `npm run verify full` no longer refers to the removed benchmarks (insights, query, cognition graduation); this broke CI for the first removal commit (`c9f3ad0`) and is fixed in `539d668`.
- The Chinese usage guide said the default tool surface was `full`; it is `core`.

## Known limits

- The removal is based on the absence of evidence of benefit or use, not on usage telemetry; Mnemora collects none.
- Schema tables for the removed features stay; dropping them is left for a later major version.
- The graph-recall canary (adaptive canary and adaptive recall, about 24 KB) was reviewed and kept for now: its shadow telemetry runs through `kg_context` by default, and the ReasoningMemory canary planned for 2.0 may reuse it.

## Verification

- Full unit suite: 1036 tests, pass (11 skipped: inspector browser tests without Chromium). The suite is 127 tests smaller than in 1.37.0 (1163): tests that covered only removed features were deleted, and new tests pin the removal boundary (removed kinds fail clearly, legacy tables upgrade and are cleared by hard forget, old config keys load).
- `npm run check`, `npm run -s plugin:validate`, `npm run -s release:validate` and the official plugin gate pass.
- Retrieval gate (100 LongMemEval_S questions, lexical): unchanged against the baseline.
- CI (Linux and Windows, Node 24.19.0 and 26.5.0, plus the retrieval gate) passed for `d163183` (run 39392478456), including `npm run verify full` benchmarks.
