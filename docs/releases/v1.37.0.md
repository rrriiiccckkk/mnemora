# v1.37.0 — Recall in the user message, time phrases, host embeddings, a retrieval gate in CI

## Highlights

- **Recall is placed in the user message by default.** The recall packet now goes at the start of the active user message instead of the system prompt (`contextEngine.recallPlacement`, `"system"` restores the old behaviour). With the same packet, preference questions (LongMemEval_S, 30, host-agent prompt) rose from 8 to 11 of 30 with lexical recall and from 8 to 16 with semantic recall (`mimo-v2.6-pro`); with `mimo-v2.6-flash`, from 7 to 14 and 5 to 18. On the 1.36 abstention set, abstention changed by one question for each reader (22 → 21, 21 → 20) and answerable questions rose (43 → 45, 41 → 46). Capture, fingerprinting and query extraction strip Mnemora's own envelope first, so a placed packet is never recorded as user speech.
- **Time phrases and relative dates.** A time phrase in the prompt ("10 days ago", "last Saturday", "last month", "上周六", "三天前") becomes a window of dates. Records recorded in it, or mentioning an event in it ("I cleaned them last month", recorded today), win near ties with records from other days. Relative dates inside recalled records are resolved against their recording time in the header (`dates=three weeks ago≈2023-05-04`), without rewriting the quote. Temporal-reasoning questions (133): `mimo-v2.6-pro` 93 → 97, `mimo-v2.6-flash` 77 → 84. Retrieval over all 500 questions is unchanged (362 → 362 with all evidence in the packet). Local and deterministic, no model calls; `unifiedRetrieval.timeAnchors: false` turns it off.
- **Semantic recall with OpenClaw's embedding provider (opt-in).** `embeddings: { enabled: true, provider: "host" }` uses the provider OpenClaw configures for its own memory search (`memory.search.*`). OpenClaw holds the credentials. Vectors are stored per host provider and model, and recall falls back to lexical when the provider is missing or failing. Through OpenClaw's Ollama adapter the vectors equal the direct Ollama path (90 texts, minimum cosine 1.0). It stays opt-in because with a hosted provider every captured turn is sent to that provider.
- **Retrieval regression gate in CI.** A new CI job runs every fifth LongMemEval_S question (100) through automatic recall, lexical, with no model calls. Ids and clock are seeded so runs repeat exactly. It fails when evidence recall drops or the records attached to unrelated prompts rise beyond the tolerance in `eval/retrieval-gate/baseline.json`. The dataset (MIT) is downloaded at a pinned revision and sha256, not committed. Checked against older builds: 1.36.0 passes, and 1.32.19 fails (all evidence 72 → 3). Local run: `npm run eval:retrieval-gate -- <longmemeval_s_cleaned.json>`, about one minute.

## Behaviour changes (please read before upgrading)

1. **Recall placement.** Automatic recall now appears at the start of the active user message. Hosts or tools that read the system prompt to find Mnemora's packet should set `contextEngine.recallPlacement: "system"`. The packet keeps its non-authoritative envelope, and in the user slot it carries no more authority than the user's own turn.
2. **Time anchors are on by default.** Prompts with a time phrase can rank records from that window above slightly closer matches from other days. A much closer match from another day still ranks first: the window breaks ties, it does not filter. Recalled records may carry a `dates=` field in their header. Days are local calendar days of the process running Mnemora.
3. **Host embeddings only when configured.** Nothing changes unless `embeddings.provider` is `"host"` (or `"host:<id>"`). The memory-core SDK is loaded only then, so importing Mnemora leaves the global fetch dispatcher (and `HTTPS_PROXY`) untouched.
4. No schema migration (still v88).

## Fixes

- Capture strips Mnemora's own recall envelope from a user turn before recording, fingerprinting or query extraction (needed for user-message placement; checked against the poisoning fixtures).
- Evaluation scripts: `MNEMORA_QA_PROMPT=agent-user` places the packet in the user message; evaluations can be made deterministic with `scripts/lib/deterministic.mjs`.
- The usage guides (English and Chinese), `docs/recall-quality.md`, `docs/development.md`, `docs/threat-model.md` and the roadmap document placement, time phrases, host embeddings and the gate.

## Known limits

- Preference results: 30 questions, two readers from one vendor, one judge.
- Time phrases: only temporal-reasoning questions in LongMemEval have dates consistent with their time phrases, so effects on other types could not be measured. Superseded facts are still marked only through the 1.34 `newer_related` links. Ambiguous forms ("next Saturday", "a few weeks ago") are not resolved to a date.
- Host embeddings: hosted models such as `text-embedding-3-small` have no calibrated thresholds yet; per-agent `memorySearch` overrides other than `scope.defaultAgentId` are not applied; `journal embed` on the command line still talks to Ollama directly.
- The retrieval gate covers lexical recall in English only; it does not run embeddings or answer questions.
