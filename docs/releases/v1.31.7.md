# Mnemora v1.31.7 — Preregistered task-resume value decision

- Adds detached, read-only `evaluate task-resume-register` and `evaluate task-resume-decision` commands. A registration binds the comparison plan, split IDs, material hashes and fixed v1.32 policy before formal runs; changed inputs or invalid chronology are rejected.
- The policy compares Mnemora against simple retrieval on held-out cases: at least +10 percentage points continuation correctness, at most half the stale-fact misuse, at most 1.2× total model tokens, and no regression in repeated steps or irrelevant injection. Missing labels, zero-token measurements, synthetic data, fewer than 20 tuning/100 test cases, or fewer than 10 baseline stale-fact cases cannot pass.
- Exact-boundary tests use integer comparisons. A zero stale-fact baseline is insufficient evidence of a halving, not a fabricated ratio of zero. Tuning rows never repair a failed held-out decision.
- A pass permits operator review only. It cannot activate a ReasoningMemory pilot, mutate recall/calibration, or establish causal/population efficacy. Hashes and self-reported timestamps require an independently timestamped pre-run record and audit; rewritten registrations cannot be disproved from a self-contained JSON file alone.
- All task-resume file evaluation commands, including the existing comparison command, now run without opening or initializing the selected memory database.
- Records the remaining poisoning threat-model, threshold-scan and implicit-usefulness work without claiming those capabilities have been implemented. The prior four-case Mac report remains exploratory; no retrospective preregistration or improved effect claim is made.
