# v1.32.13 — Respect declared validity during unified recall

Current unified retrieval now excludes graph claims and active decisions outside their declared inclusive validity windows. Filtering occurs before SQL collection limits, so newer imported expired records cannot crowd a currently valid record out. Validity bounds travel with selected candidates and are counted in prompt packing.

Exact source-history retrieval accepts an inclusive `recordedBefore` timestamp; the CLI exposes it through `INTENT=exact_history RECORDED_BEFORE=<Unix milliseconds>`. The SQL cutoff precedes LIMIT and never reads another scope. Invalid timestamps or incompatible filters fail closed. Sources remain unverified reference, and tests/publication/installation are not interchangeable completion evidence.

This is a source-record cutoff, not reconstruction of historical decision or belief lifecycle. It does not infer supersession from prose, change stored status, delete historical facts, revive forgotten sources, or enable model calls. Existing explicitly corrected task-action history remains the state authority.

Validation: targeted temporal, unified retrieval and task-continuation regressions; full offline verification and exact-commit Linux/Windows CI required before release. No efficiency benefit is claimed.
