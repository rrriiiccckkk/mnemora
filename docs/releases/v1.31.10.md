# Mnemora v1.31.10 — Threshold evaluation safeguards

- Adds a bounded, read-only threshold-scan operator command for manual unified
  retrieval's existing `hardMinScore`. Requires an explicit existing schema-83
  snapshot and never creates, migrates or writes a store.
- Freezes tuning/test separation and selection: tuning F1, then estimated
  tokens, then higher threshold. Failed tuning, negative-control violations,
  budget overruns and held-out failures cannot authorize a deployment or cause
  test-driven reselection. Reports are aggregate-only with a normalized plan hash.
- Extends the existing fictional recall-quality benchmark with a six-point
  threshold curve. Synthetic evidence remains withheld regardless of scores.
- Documents distinct parameter roles, estimated-token/latency boundaries,
  authorized snapshot handling and minimum coverage versus statistical evidence.
- This is preparatory evaluation hardening, not evidence of better recall,
  continuation accuracy or production model performance. No default, schema,
  dependency or embedding-model change; v1.32's real comparison remains pending.

Local validation: Node 24.19.0 `npm run verify` passed, including 954 unit tests,
all benchmarks, plugin validation/smoke and the documented official SDK
compatibility expectation gate. Publication requires successful Windows/Linux
CI for the exact tagged commit.
