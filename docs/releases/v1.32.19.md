# v1.32.19 — Memory argument validation and installation verification

`kg_memory` now publishes operation fields, including `query`, at the schema root
for routers that project root properties. It preserves operation-specific union
constraints and validates calls before opening storage. Invalid search/store
arguments produce a bounded, content-free tool error; missing/blank/non-string
queries cannot reach `trim`. Direct search callers also receive an explicit
validation error, and unsupported operations no longer fall through to scope
listing. Scope isolation and preview/confirm mutation requirements remain intact.

New-format source fingerprints canonicalize lockfile JSON object order and
whitespace. Installation-time formatting changes no longer falsely indicate old
source/dist; changes to dependency content still fail verification. Generated
files, package/plugin metadata and legacy fingerprint rules remain strict.

Classification and recall shadow reports now include sanitized numeric HTTP
error status codes, without provider bodies or retries. The development Mac's
Jev endpoint requires its configured proxy: the proxied synthetic trial succeeded
in 1181 ms with 665 input/55 output tokens; a direct request returned 451. This
establishes protocol compatibility through that proxy, not model quality or net
savings. No daily configuration or recall filtering policy was changed.
