# Mnemora v1.11.0 — Graph Hygiene and Local Resilience

## Graph hygiene

- Adds `kg_review` `kind: "hygiene"`, a scope-local diagnostic for
  `related_to` concentration, suspicious self-links, and pending duplicate
  review work.
- `scan: true` runs one bounded duplicate-candidate slice. It records only
  review candidates and never merges entities, deletes edges, or changes graph
  evidence.
- `quality.hygiene.enabled` is off by default. When enabled, a durable turn
  may continue a bounded duplicate scan and otherwise starts a new review only
  after the configured interval (default: weekly). Its cursor is separate from
  manual duplicate scans.

## Local embedding health

- `kg_stats` now includes `embedding_health`: an observed local state of
  `disabled`, `unobserved`, `healthy`, or `degraded`.
- The status records only model/provider identity, categorical result, and
  timestamps. It never stores a prompt, endpoint, provider body, or performs
  a live probe.
- Hybrid graph and memory search continue to fall back to lexical retrieval on
  an unavailable provider. Explicit semantic mode continues to return a
  bounded unavailable error.

## Compatibility and migration

- No schema version change. Hygiene cursors and categorical embedding health
  reuse the existing local `kg_maintenance_state` facility.
- Existing graph data, evidence, embedding bytes, manual duplicate scan state,
  recall configuration, and automatic behavior are unchanged by default.

## Validation

- Added regression coverage for bounded/resumable hygiene, no automatic merge,
  scope-local hygiene reporting, disabled/healthy/degraded embedding health,
  and lexical fallback after provider failure.
