# Mnemora v1.26.0 — Verifiable Memory Workflows

## Reliability

- Inspector graph rendering now supports multiple valid relationships between
  the same pair of entities.
- Artifact registration persists a candidate manifest before changing its
  in-memory inventory. A failed replacement leaves the existing registry
  unchanged.

## First-use and inspection

- `/mnemora verify` gives a four-step, plain-language acceptance check for
  selected ContextEngine activation, persisted capture, cross-session use, and
  an observed automatic attachment. Attachment is reported only from bounded,
  redacted telemetry.
- The Inspector now has a scope-bound memory workbench for accepted facts,
  review items, stale material, and conflicts. Known claims open their
  evidence trace directly.
- Recall explanation distinguishes the retrieval policy's prediction from a
  matching observed ContextEngine attachment. Routed queries are explicitly
  marked non-comparable rather than being treated as proof of attachment.

## Safe correction

- When Inspector operations are explicitly enabled, events, artifacts,
  episodes, and summaries can be removed through a CSRF-protected impact
  preview and a short-lived, single-use confirmation. The preview exposes only
  bounded affected counts; dependent decisions become review-only.

## Compatibility

- No schema migration, configuration default, or agent-tool contract changed.
  The Inspector remains read-only unless operations are explicitly enabled.
