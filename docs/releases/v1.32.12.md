# v1.32.12 — Preserve reported usage for failed project calls

A project adviser call that consumed reported input/cache tokens but produced
zero output previously lost that usage and appeared unknown. Such positive,
consistent provider counters now remain in private v2 measurements, including
failed-call and batch totals. All-zero counters remain unknown because they
may be host placeholders.

The bridge decodes complete bounded public Gateway JSON before checking the
CLI exit status. Known counters survive a nonzero exit, an empty answer or a
response-contract failure; those calls still fail and cannot become successful
answers. Missing, malformed, truncated or overflowing responses retain unknown
usage, and an incomplete batch total stays unknown. No pricing, raw prompts,
replies or proxy fixture counters enter measurement logs.

This is failure-accounting reliability for project development tooling. It
does not establish token savings, dollar billing or development efficiency,
backfill historical unknown calls, or change daily-host memory policy.

Validation: 16 targeted checks passed; full verification passed 1101 tests
with zero failures and one platform-specific skip, all 13 benchmark scripts
and 17 task-resume checks. An isolated installed OpenClaw 2026.9.8 real-provider
Gateway passed restart persistence, uppercase/lowercase task recall and foreign
scope exclusion. Failure responses were synthetic; no paid failures were
intentionally induced.
