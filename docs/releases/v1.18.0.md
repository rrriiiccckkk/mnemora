# Mnemora v1.18.0 — Schema-Drift Review Closure

## Complete the human review loop

- `kg_review` `kind: "worklist"` now includes scope-local schema-drift
  candidates alongside related-edge proposals and suspicious self-links.
- A schema-drift candidate can be explicitly rejected through the existing
  `kg_review` surface using preview plus the matching confirmation hash. The
  decision is durable and auditable, but it never mutates graph facts.
- A rejected schema-drift candidate cannot later be repaired through a
  different path. Existing repair confirmation remains the only accepted
  outcome and continues to preserve source-linked evidence.
- When an old candidate is now covered by the built-in endpoint vocabulary,
  it is recorded as `invalidated` review metadata. No candidate, edge,
  observation, or entity is deleted.

## Ontology coverage without identity inference

- The `uses` relation now accepts `person → product|technology` as well as
  `company → product|technology`. A KOL or other individual using a product
  therefore no longer produces a false schema-drift candidate.
- This is not automatic entity retyping. An account or endpoint mismatch is
  not sufficient evidence to relabel a person or company.

## Compatibility and validation

- Schema v76 is additive: it adds review and invalidation metadata tables;
  existing graph entities, edges, observations, candidates, and PPR policy are
  retained unchanged.
- No configuration defaults changed. `related_to` remains a connectivity
  bridge at its existing PPR multiplier, and ReasoningMemory delivery remains
  shadow-only.
