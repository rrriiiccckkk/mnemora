# Mnemora v1.32.3 — Lossless compact resume payloads

- Optional `resume --format compact` and public `renderTaskResumeMemory` render
  authorized projections with a shared reference table. Default output is unchanged.
- All text, state sections, provenance, timestamps, scope, evidence coverage and
  truncation flags survive expansion unchanged. Literal references in prose are
  never rewritten. Source excerpts remain unverified data, not instructions.
- Small payloads fall back to the original representation when reference-table
  overhead would increase UTF-8 bytes. Byte savings are not tokenizer measurements.
- Lifecycle, limited-view and CLI tests verify lossless output and preservation
  of existing forgotten-source semantics. This is not a new evidence policy.

Schema 84, automatic recall, product defaults and model identities are unchanged.
No migration, production database access, paid model call or efficacy claim is
part of this development. Compact reference comprehension and real token savings
still require an authorized matched regression. Formal experiment requirements
and the v1.33 gate remain unchanged.

Node 24.19.0 complete local `npm run verify` passed: 1055 unit tests passed,
one POSIX-only permission test skipped on Windows, all existing benchmarks,
plugin validation, smoke and version checks passed. Independent Standards and
Spec reviews found no actionable issues. The known OpenClaw 2026.9.2 advanced
metadata rejection remains an expectation gate, not universal compatibility.
