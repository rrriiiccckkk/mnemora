# Mnemora v1.28.0 — Reliable Task Continuation

## Reliable OpenClaw lifecycle

- Durable turn capture now uses the host's stable receipt and message-range
  identities to deduplicate compatible lifecycle callbacks without confusing
  equal content from separate turns.
- Durable admission applies configured agent exclusions using the verified host
  identity, including when message objects do not expose an agent id.
- `/mnemora verify start` creates a short-lived, scope-bound opaque marker.
  A cross-session verification succeeds only after that marker's persisted
  user turn is actually attached in a different session; aggregate telemetry
  or an unrelated attachment cannot satisfy it.
- When local ContextEngine compaction declines before making a rewrite, the
  imminent-overflow call delegates safely to OpenClaw. A result with unknown
  runtime rewrite state is never retried or delegated, avoiding double
  compaction.

## Task continuation

- Adds the read-only `mnemora resume` operator command and Inspector Task
  resume view. They project existing task episodes, confirmed decisions,
  outcomes, constraints, and source references without changing automatic
  recall, prompt delivery, or task authorization.
- Ambiguous task names return bounded candidates; task identity, source scope,
  superseded decisions, forgotten evidence, failed outcomes, and empty state
  remain explicit rather than being inferred as progress.
- Adds 24 deterministic, offline task-resume evaluation cases covering normal
  continuation, decision replacement, ambiguity, scope isolation, forgetting,
  failure, and no-memory states. This functional baseline is not a model or
  real-world task-effect experiment.

## Compatibility

- Schema advances from v78 to v80 through additive local migrations for
  durable turn identity and privacy-preserving first-use verification state.
- Mnemora now declares the OpenClaw `2026.9.2+` / Node.js `>=24.15.0 <25`
  support line. Node 24.14 is rejected by the host SQLite safety requirement.

## Validation

- Type checking and the supported-Node full local unit runner pass. The GitHub
  release workflow still requires a successful exact-commit CI run on both
  Windows and Linux before publishing this release.
