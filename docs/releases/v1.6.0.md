# Mnemora v1.6.0

## Verification receipt-expiry safety

ReasoningMemory verification now has the same expiry boundary as delivery
feedback. A receipt can authorize deterministic verification only while its
existing `itemRetentionDays` window is open.

- A new tool result or TaskOutcome referring to an expired receipt is ignored.
- A pending check that expires before the bounded local worker runs is retained
  for audit with terminal status `expired`; it never opens a memory circuit.
- `runtime-verification-summary` is now `reasoning-verification-summary-v2`
  and reports `expired` separately from processed matches and mismatches.

## Compatibility

Schema 67 rebuilds only the local verification-event ledger so its status
constraint can represent `expired`. It copies every pre-existing verifier
event byte-for-byte, including identifiers, receipt links, assertion values,
verdicts, state, and timestamps. No strategy, belief, graph data, feedback,
or delivery circuit is rewritten. Configuration and default behavior are
unchanged: verification remains disabled unless explicitly enabled.
