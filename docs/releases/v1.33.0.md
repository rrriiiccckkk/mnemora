# v1.33.0 — Relevance-ranked recall, per-agent isolation and a slimmer plugin

## Highlights

- **Automatic recall now ranks by relevance.** On LongMemEval_S (500 questions, 800-token budget), the answer session is injected for 93.8% of answerable questions (was 9.8%) and an answer turn for 83.2% (was 5.5%), on par with a same-budget bm25 baseline (94.9% / 81.5%). Median `assemble()` latency went from 47 ms to 16 ms. See `docs/recall-quality.md`.
- **Per-agent memory isolation.** Automatic memory and manual tools are isolated per agent by default.
- **Slimmer plugin.** The experimental ReasoningMemory pipeline was removed (about 4.5k lines), and the default tool surface is now `core`.

## Behaviour changes (please read before upgrading)

1. **Schema v86.** Adds a chunked FTS5 journal index. Migration is additive; the index is built for existing journal events the first time the database opens.
2. **`scope.isolation` defaults to `"agent"`.** Each non-default agent reads and writes `agent:<id>`, and the default agent (`scope.defaultAgentId`, default `main`) keeps `scope.default`. Multi-agent installations that relied on a shared scope should set `scope.isolation: "shared"`. For non-default agents, cross-scope admin tools (`kg_stats`, `kg_scopes`, `kg_forget`, `kg_merge`, `kg_merge_undo`, `kg_export`, `kg_import`, `kg_embed_backfill`) are not registered.
3. **`toolSurface` defaults to `"core"`** (10 tools). Set `toolSurface: "full"` to keep all 32.
4. **ReasoningMemory removed.** `cognition.reasoningRuntime` and `cognition.reasoningCuration` are still accepted, so existing configuration keeps loading, but they are ignored. The `mnemora reasoning` CLI family was removed. Existing tables stay in place.

## Fixes

- Journal search used per-word substring matches capped to the newest 40 rows. It now uses a bm25-ranked chunk index with Intl word segmentation (Chinese supported) and stopwords.
- Retrieval scores ignored the query (constant base of 1). They now include relevance and term coverage.
- Facts beyond the first 1200 characters of a message could never be recalled. Messages are now indexed in chunks and excerpted around the match.
- The anchor filter ran after budget truncation. It now runs before truncation.
- Newlines were collapsed before role-line quoting, which let an injected `system:` line slip through. Newlines are now preserved, and inline role and override patterns (English and Chinese) are quoted.
- Forget, tombstone and redaction now purge the search index through triggers, and restore rebuilds it.
- One shared graph connection per runtime (closed at `gateway_stop`), plus a migrate fast path. This fixes the per-operation reopen and the file-descriptor build-up.
- Browser tests are skipped cleanly when Chromium is missing, so the test server no longer leaks.

## Known limits

- When the answer is not in history, recall still injects the best lexical matches. A relevance floor is the next step.
- Preference-style questions trail bm25 (56.7% vs 70.0%), so semantic or hybrid recall is needed for them.
- End-to-end answer accuracy is not yet measured.
