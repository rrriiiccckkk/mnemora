# v1.34.0 — Semantic journal recall, relevance gating and knowledge-update links

## Highlights

- **Semantic journal recall (opt-in with `embeddings.enabled`).** Captured turns are embedded by your local Ollama model after each turn, and automatic recall fuses bm25 with cosine similarity. On a 60-question LongMemEval_S subset with `all-minilm`, preference questions reach 73.3% session hit (lexical: 53.3%), while memory is attached for 66.7% of foreign questions (lexical: 85.0%) and 33.3% of off-topic prompts (lexical: 75.0%). See `docs/recall-quality.md`.
- **Relevance gating.** With embeddings, a lexical hit must also be semantically close to the prompt, and a minimum rarity-weighted term match (`unifiedRetrieval.minQueryMatch`, default 0.15) applies. Without embeddings recall behaves as in 1.33: measured, a lexical floor alone costs more recall than it saves.
- **Knowledge-update links.** When an earlier and a later record on the same topic are both attached, the earlier one carries `newer_related=<n>` and the envelope says the most recent statement is current.
- **Chinese compound words.** Prompts such as "帮我订餐" now match "订餐" in history.
- **Fixed recall probes in CI.** `scripts/benchmark-recall-probes.mjs` covers Chinese under noise, a fact deep in a long message, injected role lines, cross-agent isolation, knowledge updates and an unrelated prompt.

## Behaviour changes (please read before upgrading)

1. **Schema v87.** Adds `mnemora_conversation_event_chunks_embeddings` for journal chunk vectors. The migration is additive. Vectors are deleted with their chunks on forget, tombstone, redaction and restore.
2. **With `embeddings.enabled: true`, recall changes.** Lexical hits outside the prompt's semantic neighbourhood are no longer attached, and records that share no words with the prompt can be. Thresholds `unifiedRetrieval.semantic.minSimilarity` (0.45) and `gateSimilarity` (0.2) are calibrated on `all-minilm`; recalibrate for other models. Set `unifiedRetrieval.semantic.enabled: false` to keep 1.33 behaviour with embeddings on.
3. **Existing history needs one backfill** before semantic recall covers it: `MNEMORA_DB=~/.openclaw/mnemora.db node dist/cli.js journal embed --model <model>`. New turns are embedded automatically (`semantic.embedPerTurn`, default 128 chunks per turn). Records without a vector are never dropped by the semantic gate.
4. **Recall envelope.** Earlier related records may carry `newer_related=<n>`, followed by a guidance line. Recall consumers that parse the envelope strictly should allow the new attribute.
5. **LongMemEval script.** The benchmark id is now `longmemeval-s-retrieval-v2`. It accepts a `start:end` range and an output file, adds foreign-question and off-topic probes, and supports `MNEMORA_EVAL_EMBED_MODEL`.

## Fixes

- Light stemming lets the relevance floor and knowledge-update links match inflected forms. Ranking keeps exact words, because stemming lowered recall when measured.
- FTS match expressions apply the index's Chinese segmentation to each query term.
- `journal embed` CLI: `--model` (required), `--base-url`, `--scope`, `--limit`; resumable.
- Removed the obsolete ReasoningMemory dataset document.
- README rewritten in English and Chinese, including how recall works, the key settings and recall results.

## Known limits

- Abstention: when the answer is absent, the closest records are still attached, with or without embeddings.
- Semantic results come from a 60-question sample with one English model. Chinese needs a multilingual model, which has not been calibrated here.
- End-to-end answer accuracy is not yet measured.
