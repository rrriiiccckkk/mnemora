# Mnemora v1.20.0 — Reliability Hardening

## Inspector correctness

- The local Inspector now constructs a complete graph before calculating node
  degree for display. Non-empty graph rendering no longer asks Graphology for
  a node before it exists.
- Business entity type is no longer passed through Sigma's reserved renderer
  `type` attribute. This prevents valid entities such as `company` from being
  interpreted as missing custom renderer programs.
- Inspector client TypeScript is now checked with the bundler-oriented browser
  build configuration during `npm run check`. A real browser regression test
  covers a graph containing nodes and a relationship.

## Artifact registry safety

- New artifact registrations stop explicitly at 1,000 entries, preserving all
  existing registrations and artifact files. Mnemora does not automatically
  prune backups or recovery points.
- Valid legacy manifests above that admission cap remain recoverable after a
  restart.
- A damaged or oversized manifest is reported as a bounded degraded health
  state (`manifest_invalid` or `manifest_too_large`); artifact access returns
  `artifact_registry_unavailable` rather than silently reporting an empty
  registry.

## Compatibility

- No configuration defaults changed.
- No database schema migration is required.
- PPR/traversal policy and ReasoningMemory delivery remain unchanged.
