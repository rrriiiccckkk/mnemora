# Mnemora v1.9.0

## Governed delivery readiness

ReasoningMemory runtime calls now retain a scope-local snapshot of the
normalized policy that was actually used by the live ContextEngine. The
operator CLI uses this snapshot for readiness, calibration, and canary checks,
so it does not need to reconstruct plugin settings from separate environment
variables.

The snapshot contains only bounded runtime controls and a policy hash. It does
not contain prompts, strategy text, memory IDs, evidence, sources, session
identifiers, provider credentials, or model output.

`mnemora cognition reasoning runtime-diagnostics --scope <scope>` now returns
one read-only report covering the observed policy, readiness gates, candidate
and selection rates, semantic/matching exclusions, canary state, delivery
feedback, and the explicit `not_measured` efficacy boundary.

Before the live runtime has observed a policy for a scope, diagnostics returns
`policy_not_observed`; it cannot make a scope ready or enable delivery. The
existing explicit calibration, exact-scope canary, rollback, verification, and
per-memory circuit requirements remain unchanged.

## Schema migration

Schema 70 adds `mnemora_reasoning_runtime_policy_snapshots`. The migration is
additive and does not backfill snapshots, invoke a model, alter existing
telemetry/calibrations/canaries, or enable delivery.

## Validation

Validated on Node.js 24 with typechecking, complete tests, offline benchmarks,
smoke testing, plugin and official compatibility validation, and release
metadata checks.
