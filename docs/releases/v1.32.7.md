# v1.32.7 — Persistent project memory adviser

Mnemora development can now retain project memory between independent command
invocations. In a repository checkout, `npm run dev:memory -- status` inspects
project state without a model call; `npm run dev:memory -- ask --message "..."`
starts a fresh session against the same `project:mnemora` database. A bounded
UTF-8 note can also be supplied with `--file`.

Each request runs its own loopback Gateway and stops it afterward, using a
versioned snapshot of the installed Mnemora plugin. The existing daily Gateway
provides model inference through its public stateless interface; provider
credentials and the daily memory database are not copied. The project database,
workspace and state remain in the ignored `.dogfood/project-mnemora` directory.

The entry validates inputs before inference, rejects concurrent project runs,
and verifies durable user/assistant capture, preservation of previous event IDs
and persistence after Gateway shutdown. Regression tests cover invalid input,
message bounds and literal argument forwarding. Development guidance describes
how Codex consults prior decisions and records actual verification results.

Reasoning delivery remains disabled. Unified retrieval attaches bounded memory
with shadow telemetry. The text-only model bridge is a memory adviser; Codex
performs code changes and tests separately. This command is a repository
development tool, not an automatically installed service or a tool-capable agent.
No database schema or plugin runtime policy changes are introduced.

Local verification passed with 1080 unit tests, all script benchmarks and 17
task-resume evaluations; one Windows-specific ACL test was skipped on macOS.
Installed OpenClaw 2026.9.8 integration and independent real-model project calls
verified cross-process recall and durable capture. These checks establish wiring
and persistence, not measured development-speed or token savings. Publication
also requires successful Linux and Windows CI for this exact release commit.
