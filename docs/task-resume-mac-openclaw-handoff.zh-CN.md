# 交给 Mac 上的 OpenClaw：准备真实任务续接对照材料

你是**材料准备与实验执行 Agent**，不是只等材料的标注 Agent。请在 Mac 上使用你已获授权访问的 OpenClaw 会话、Mnemora 公共接口和模型运行记录，主动完成下面的收集与三组运行，再将材料交给[标注 Agent 交接单](task-resume-labeling-handoff.zh-CN.md)。不要把“缺四类材料”原样退还用户，也不要编造缺失数据。

## 边界

- 原始会话与身份映射只留在本机获授权的工作区；实验输入先去标识化，并将去标识化的提示、附件、输出留在受控目录。不要把这些材料提交到公开仓库、粘贴到聊天或交给未授权服务。向有权访问的标注 Agent 提供本机受控路径。对外报告只用去标识化案例 ID。
- 只选用户授权范围内的真实任务；不直接查询或复制生产 SQLite、WAL、SHM 文件来凑数据。通过 OpenClaw/Mnemora 已公开、受支持的接口导出必要信息。实验写入使用独立的一次性环境，不能污染日常记忆。
- 先核实本机是否有可用的真实历史、模型调用和用量日志，以及能否隔离三组运行。不要假定某个 CLI、插件 hook 或日志字段一定存在；记下实际使用的接口和版本。如果某项能力不可用，说明已检查的入口、受影响案例和最小可行的替代方案，不得用估算值冒充实测。

## 执行顺序

1. **盘点并选案例。** 从有权访问的多会话任务中找可核对的续接点，覆盖中文任务，并尽量包含更正/替代、失败尝试、遗忘和进程重启。每例在续接点之前截断历史，保存该时点的历史及来源引用；另建立不提供给模型的“当时有效状态”依据：已完成、失败、阻塞、约束、下一步、过期信息。不能从待评模型回答反推真值。若没有任何合规可用案例，列出具体候选与所缺授权/记录，停在此步。
2. **冻结实验计划。** 以 [`fixtures/task-resume-comparison-plan-v1.json`](../fixtures/task-resume-comparison-plan-v1.json) 为结构建立真实 `planned` JSON，填写实际 `modelId`、`historySetId`、`taskSetId`、`tokenBudget`、`latencyBudgetMs` 和互不重叠的 tuning/test ID；两组至少各一例。`synthetic-*` 仅是示例，不能当真实案例。记录模型确切版本、采样设置、系统指令、续接问题、预算计算口径、案例筛选与排除理由。先用 tuning 固定检索方式、提示格式和判定口径，再运行 held-out test；不能看 test 结果后调参或换案例。
3. **固定三组记忆条件。** 对同一案例，三组基于同一份截断历史构建记忆，但模型都只看到同一段续接点当前会话、同一问题、同一模型、非记忆指令和预算；不能把完整历史直接放进某一组的提示。仅附加的长期记忆条件不同。`no_long_term_memory` 不附加长期记忆；`simple_retrieval` 对同一历史使用预先写明的简单词法检索/top-k，不使用 Mnemora 图谱或治理结果；`mnemora` 使用隔离环境中由同一历史形成的 Mnemora 记忆，并保留来源引用。Mnemora 的只读 `resume <query> --scope <scope>` 或 `resume --task-ref <ref> --scope <scope>` 可辅助核对投影；若评估的是自动注入效果，必须捕获**实际模型可见的附加内容**，不能把 `resume` 查询结果冒充自动注入。按本机受支持的方式隔离各组，防止上一组输出进入下一组记忆。
4. **实际运行并留痕。** 每例 × 三组各调用模型一次，保存完整模型可见提示、所附记忆、实际输出、运行配置、模型/供应商返回的总 token 数和端到端毫秒数。记录每次开始/结束时间及计量来源；不能从字数推算 token。预算超限或其他条件不一致的运行单独标为协议违例，不塞进有效结果；修复运行条件后才可重跑，并保留重跑原因。`irrelevantMemoryInjected` 的证据必须来自实际附加内容，不能从回答猜测。
5. **交接标注。** 将下面的本机材料交给有权访问的标注 Agent，请它按[标注交接单](task-resume-labeling-handoff.zh-CN.md)核对标签，产出 `measured-plan.json` 和 `annotation-audit.md`。实验执行程序或 `evaluate task-resume-comparison` 命令不会替你运行模型、核实真值或完成标注。

## 本机交付清单

- `planned-plan.json`：冻结后的真实计划与三组定义。
- `cases/`：每例的截断历史、续接问题、独立真值、相关更正/遗忘记录及来源引用；原文仅留受控目录。
- `runs/`：每例 × 每组的完整模型可见输入、附加记忆、输出、实际 token/耗时日志及运行配置。
- `collection-audit.md`：数据来源与授权范围、去标识化方法、案例筛选、三组隔离办法、简单检索规则、模型版本、计量来源、协议违例和重跑记录，以及交给标注 Agent 的受控路径。

完成时只向用户报告：真实案例数、三组运行数、是否已交给标注 Agent、尚待裁决的具体事项及脱敏后的结果路径。材料不齐时，报告**已经拿到什么、具体缺什么、已尝试哪个受支持的入口、下一步需谁作何决定**；不要生成 `measured` 文件，也不要声称已证明效果。最小案例数只保证流程可验收，不构成有效性的统计证明。
